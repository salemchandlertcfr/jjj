# Situações que precisam ficar explícitas

S13 §13.

| Situação | Conduta |
| --- | --- |
| Não há esp da área | Ficha sem skill, bloco marcado, fontes para afirmações centrais e lacuna. |
| Pedem para criar agora | Não gerar durante o projeto; seguir marcado ou abrir curadoria separada por decisão da pessoa. |
| Pedem pessoa/credencial | Usar escola com obras ou nome funcional; não imitar nem inventar experiência. |
| Veto deixa causa central descoberta | Respeitar, registrar risco e perguntar que outra especialidade cobre. |
| Muitas especialidades para a dose | Sugestão de cobertura, reserva e sinal de subir dose se central ficar sem ninguém. |
| Duas escolas relevantes | Obras e divergência explícita; não repetir a mesma contribuição com outro nome. |
| Domínio sensível | Limites e necessidade de revisão profissional; agente não é profissional habilitado. |
| Pesquisa contradiz esp | Evidência prevalece, errata, situação em revisão. |
| Mesmo modelo na elaboração/verificação | Permitido modelo igual; sessões produtoras não podem verificar. |
| Modelo muda ou validade vence | Registrar e retestar, sem fabricar validação. |
| Selo ou transporte divergente | Refazer a execução; repetição exige investigar adaptador. |
| Área sem gabarito | Rubrica cega por dois avaliadores; mesma regra numérica de admissão. |
| Biblioteca vazia | Recrutar pelo problema, todos marcados; não simular especialidades prontas. |

As integrações Notion/Claude Code são contratos de adaptação, não conectores
implementados. Bloco no topo, material longo depois, tarefa ao fim. Confira
primeira mensagem efetiva e selo. Não abrir workspace para um agente cego
carregar esp; o conteúdo já deve estar no brief filtrado.
